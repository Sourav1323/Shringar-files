Why are Entities inside "model/"?

Package Naming Convention Clarification

In Spring Boot and Enterprise Java architectures, model and entity are two names for the exact same architectural layer (the Domain Layer).

📁 shringar-backend/src/main/java/com/shringar/model/
• User.java (@Entity)
• Booking.java (@Entity)
• Design.java (@Entity)
• Artist.java (@Entity)
• Coupon.java (@Entity)
• CustomerConcern.java
• Cart.java (@Entity)
• Payment.java (@Entity)

Every class in com.shringar.model has the @Entity and @Table annotations and maps directly to MySQL database tables. If you prefer the folder to be named entity/, we can rename the package with zero disruption.

How Functions Are Made & Run

Full Request-Response Lifecycle Flow

1
Browser / UI Trigger:

User clicks button (e.g. "Send OTP" or "Create Booking"). JavaScript dispatches an asynchronous fetch('/api/auth/signup') request.

2
Security Filter Gate:

JwtAuthFilter intercepts the HTTP header. If it's a protected route like /admin/**, it verifies the JWT signature and extracts the user's role.

3
Controller -> Service -> Repository:

AuthController receives DTO, calls AuthService for business validation, and uses UserRepository (Spring Data JPA) to execute SQL queries on MySQL.
